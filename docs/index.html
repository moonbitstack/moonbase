The thirteen encodings

Every package exposes the same five functions in the same order, so reading one is reading all of them. Variants are a named argument, not a different function name.

@base2

One bit a character

Eight characters a byte, no padding, no waiting. The multibase 0 prefix.

@base8

Three bits a character

Eight characters to three bytes. A bit packing, not an octal of a number — the difference is a leading zero byte.

@base10

Decimal

The bytes as one big-endian integer. The only base whose output a human reads without a legend.

@base16

Hexadecimal

Two characters per byte, so leading zeros survive. A colon form writes certificate fingerprints.

@base32

RFC 4648 base32

The A-Z2-7 alphabet, a hex kind that sorts like the bytes it encodes, Crockford and z-base-32 for people.

@base36

0–9a–z

Case-insensitive, alphanumeric. Short, human-facing ids. Has an integer mode too.

@base45

RFC 9285

Two bytes in three characters a QR code's alphanumeric mode can hold, so the data fits in a smaller symbol.

@base58

No look-alikes

0, O, I and l are left out so strings survive being read aloud. Bitcoin, Flickr and Ripple alphabets, plus base58check.

@base62

0–9A–Za–z

Fully URL-safe. The usual choice for shortened links and opaque public ids.

@base64

RFC 4648 base64

Standard +/ and a URL-safe -_ kind for tokens and file names.

@base85

Four bytes, five characters

Adobe's Ascii85, ZeroMQ's Z85 (RFC 32) and the IPv6 spelling of RFC 1924 — three alphabets, one width.

@bech32

BIP 173, BIP 350

A readable prefix, five-bit groups and a BCH checksum that makes a typo visible anywhere — including in the prefix.

@multibase

Self-identifying

One character in front of any of the above, from 0 for base2 to a rocket for base256emoji.

Note

The demo runs the encoders in JavaScript, ported from the MoonBit sources. scripts/check_docs.py replays the library's own vectors — multibase's tests/*.csv fixtures and every specification example — through that port, so a drift between the demo and the library fails the build. base10, base36, base58 and base62 read the bytes as one big integer; the rest pack bits, except base45 and base85, which group bytes into a number first.

What it gives you

One shape

All thirteen packages share the five faces: encode, encode_bytes, decode, decode_bytes and decode_lossy. Import only what you use — an app that needs base64 does not link base58's big-integer core.

// the ordinary case
@base64.encode(data[:])                           // "bW9vbmJhc2U="
@base64.encode(data[:], kind=Url, padding=false)  // "bW9vbmJhc2U"

// a wire format that already holds bytes — no round trip through String
@base64.encode_bytes(data[:])

Streaming

Every bit-packing package has a sink() and a source(). Feed them whatever chunks the transport hands you; the bytes that come out are the bytes one call would have produced.

let sink = @base64.sink()
sink.write(b"moon"[:])
sink.write(b"base"[:])
sink.finish()                    // "bW9vbmJhc2U="

Honest errors

A bad input names where it broke, instead of a silent None. The four failures are Bad, Truncated, Padding and Checksum, each carrying the offending index.

try @base64.decode("Zm*vYg==") catch {
  failure => match failure {
    Bad(at~, char~)      => // at = 2, char = '*'
    Truncated(at~)       => // input ends mid-group
    Padding(at~)         => // '=' where it cannot be
    Checksum(at~)        => // a carried checksum did not match
  }
} noraise { _ => println("decoded") }

Self-identifying strings

multibase writes the encoding's name in front of the string; bech32 folds the prefix into the checksum. Either way the reader does not have to be told which encoding it was handed.

@multibase.encode(data[:], base=Base58Btc)  // "zKJfFLz7PRba"
@multibase.decode("zKJfFLz7PRba")           // b"moonbase"
@bech32.encode("moonbase", data[:])         // "moonbase1d4hk7mnzv9ek2s84pra"

Custom alphabets

The positional core is public, so any base-N system is two lines. Alphabet::new fails on a bad alphabet (it often comes from configuration); Alphabet::of is the same thing for literals in your own source.

let crockford = @moonbase.Alphabet::new(
  "0123456789ABCDEFGHJKMNPQRSTVWXYZ",
)
@moonbase.encode(data[:], crockford)
